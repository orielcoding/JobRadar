## 0. דרישות מוקדמות 🧑

1. **Python 3.10 ומעלה.** בודקים עם `python3 --version` (ב‑Windows: `python --version`). אם אין, מורידים מ‑python.org. ב‑Windows מסמנים בהתקנה "Add to PATH".
2. **Claude Code:**
   - Mac או Linux: `curl -fsSL https://claude.ai/install.sh | bash`
   - Windows (PowerShell): `irm https://claude.ai/install.ps1 | iex`

   אחרי ההתקנה פותחים טרמינל חדש ומריצים `claude`. מתחברים עם חשבון הפרו בדפדפן ויוצאים עם `/exit`.
3. **המחשב צריך להיות דולק או במצב שינה בשעת ההרצה.** ב‑Mac וב‑Windows הרצה שהוחמצה בזמן שינה תתבצע כשהמחשב יתעורר. אם הוא כבוי לגמרי, ההרצה מדלגת ליום הבא.

## 1. התקנה ⌨️

```bash
cd ~/jobradar                         # התיקייה שחילצת
python3 -m venv .venv
source .venv/bin/activate             # Windows: .venv\Scripts\activate
pip install -e .
jobradar init
```

`init` יוצר את קבצי ההגדרות מהתבניות ואת `.env` עם שם נושא ntfy אקראי ופרטי. מעכשיו מריצים כל פקודה מתוך התיקייה הזו, אחרי `activate`.

## 2. פרופיל וקו״ח ✍️ (השלב הכי חשוב)

1. פותחים שיחה חדשה ב‑claude.ai ומצרפים את קובץ הקו״ח.
2. מדביקים את כל התוכן שמתחת לקו בקובץ `prompts/profile_interview.md`.
3. עונים על השאלות. הראיון מחפש ראיות ("מה בנית, באיזה היקף, מה יצא"), דברים שהקו״ח לא מראים, תפקידים קרובים וגם מה פוסל מבחינתך.
4. בסוף מקבלים שני קטעים:
   - את הראשון שומרים כ‑`profile/profile.md` (במקום התבנית).
   - את השני שומרים כ‑`profile/cv.md`.

שלושה דגשים:
- **`cv.md` הוא "קו״ח אב": מאגר של כל השורות האמיתיות מכל גרסאות הקו״ח שלך, בלי טענות חדשות.** המודל מרכיב ממנו בראש את הקו״ח הטוב ביותר בעמוד אחד לכל משרה, מנחש איך מגייס יראה אותו (ציון "מעבר סינון"), ואומר לך אילו שורות לבחור.
- את הפרופיל אפשר לערוך מתי שרוצים. כל שינוי נכנס לתוקף כבר בהרצה הבאה.
- הערות בתוך `<!-- -->` הן בשבילך. המודל לא רואה אותן.

## 3. חברות ✍️ ⌨️

הגישה: **לא מגבילים לחברות מסוימות.** הפרופיל מחליט מה מתאים. חברות שמעניינות אותך במיוחד מסומנות ⭐ ומקבלות עדיפות. יש שלושה חלקים:

**א. כיסוי רחב לפי תפקיד (מומלץ).** ב‑`config/config.yaml` מדליקים את הפיד היומי של Israeli Tech Map: כ‑4,000 משרות הייטק בישראל, מחולקות לפי תחום.
```yaml
techmap:
  enabled: true
  categories: [software, data-science]     # לפי הפרופיל שלך
```
ומוסיפים כ‑180 חברות ישראליות שהמערכת יודעת לקרוא מהן תיאורי משרה מלאים:
```bash
jobradar import-techmap --dry-run                 # רק להציג
jobradar import-techmap --sizes m,l,xl            # להוסיף (s=11-50, m=51-200, l=201-1000, xl=1001+)
```

**ב. מועדפות ⭐.** ב‑`config/companies.yaml` מוסיפים `favorite: true`. אם לחברה אין אתר קריירה נתמך, מספיק השם:
```yaml
  - name: Wix
    favorite: true
```
חברה מועדפת מדלגת על הסינון המהיר, מקבלת רף פינג נמוך יותר ומופיעה עם ⭐.

**ג. חברות ספציפיות שלא ברשימה.** לכל חברה כזו מעתיקים קישור לדף הקריירה, ונותנים לכלי לזהות באיזו מערכת גיוס היא משתמשת:

```bash
jobradar detect https://www.riskified.com/careers https://jobs.lever.co/someco --add
```

- ✅ הרשומה נוספת ל‑`config/companies.yaml`. כדאי לעבור על שמות החברות.
- ❌ "no known ATS found": החברה טוענת משרות ב‑JavaScript או משתמשת במערכת שעוד לא נתמכת. אם היא מפרסמת בלינקדין, היא תגיע דרך התראות המייל (שלב 7).

אחר כך בודקים שהמשיכה עובדת:

```bash
jobradar test-sources
```

**על המכסה:** כל משרה שעוברת את המסננים עולה קצת בסינון המהיר. עם כיסוי רחב, ההרצה הראשונה מתפרסת על 2–3 ימים, וזה תקין. המסננים בשלב 4 חוסכים את רוב העלות.

## 4. מסננים ✍️

`config/filters.yaml` כבר מוגדר לפי מה שבחרת:

| נפסל בכותרת | דוגמאות |
|---|---|
| בכירות | Senior, Sr, Principal, Staff, Lead / Team Lead / Tech Lead, Architect, Director, Head of, VP, בכיר, ראש צוות |
| חומרה ושבבים | chip, ASIC, FPGA, RTL, VLSI, physical design, DFT, verification engineer, analog, PCB, silicon, hardware, electrical, אלקטרוניקה |
| צמוד חומרה | embedded, firmware, BSP, hardware validation |
| כללי | intern, student (אם אתה סטודנט, מחק את השורה) |

**חריגים:** "Lead Generation" לא נפסל.

**שנות ניסיון:** משרה שדורשת **5 שנים ומעלה** נפסלת (`experience.max_years_required: 4`). נספרות רק דרישות אמיתיות: שורות של "יתרון" או "nice to have" לא נספרות, ובטווח כמו "3‑5 years" נספר המספר הנמוך.

בדקתי את הכללים על כ‑3,900 כותרות משרה אמיתיות מישראל. אחרי המשיכה הראשונה, בודקים אותם על המשרות שלך:
```bash
jobradar filter-test           # מה כל כלל פוסל, עם דוגמאות. לא משנה כלום
jobradar filter-test --apply   # אחרי שינוי בקובץ: מחיל מחדש על משרות שהמודל עוד לא ראה
```
אם כלל פוסל משהו שלא היה צריך, מוסיפים חריג ב‑`title.exceptions` במקום למחוק את הכלל.

עוד דברים לבדוק בקובץ:
- `locations.allow_any_of`: כבר יש רשימה של ישראל.
- `workplace.allow`: למשל רק hybrid או remote.

כלל אצבע: לשים כאן רק דברים ודאיים. כל מה שדורש שיקול דעת עדיף להשאיר למודל.

## 5. התראות לטלפון 🧑

1. מתקינים **ntfy** מה‑App Store או מ‑Google Play. האפליקציה חינמית ולא דורשת חשבון.
2. בקובץ `.env` מעתיקים את הערך של `NTFY_TOPIC` (משהו כמו `jobradar-abc123...`).
3. באפליקציה לוחצים ➕ ומזינים את שם הנושא בדיוק.
4. שולחים פינג ניסיון: `jobradar doctor --ping`

שם הנושא פועל כמו סיסמה: כל מי שיודע אותו יכול לקרוא את ההתראות, אז לא משתפים אותו.

רוצים טלגרם במקום? ממלאים ב‑`.env` את `TELEGRAM_BOT_TOKEN` (בוט חדש דרך @BotFather) ואת `TELEGRAM_CHAT_ID`, ומשנים ב‑`config.yaml` את השורה `notify.channels: [telegram]`.

## 6. טוקן להרצה מתוזמנת 🧑 (מומלץ)

```bash
claude setup-token
```

מאשרים בדפדפן, מעתיקים את הטוקן שמודפס ומדביקים ב‑`.env`:

```
CLAUDE_CODE_OAUTH_TOKEN=...
```

הטוקן תקף לשנה ומשתמש במנוי הפרו, לא ב‑API. בלעדיו המערכת משתמשת בהתחברות הרגילה, שלפעמים לא זמינה להרצה ברקע. **תזכורת לחידוש: בעוד שנה.**

## 7. לינקדין והתראות מייל 🧑 (אופציונלי)

הכלי לא נכנס ללינקדין. הוא קורא את מיילי ההתראות שלינקדין שולח לך. כך אין סיכון לחשבון.

1. **בלינקדין:** מחפשים משרות עם המילים והמיקום הרצויים ומדליקים "Set alert" (או "Job alert"), בתדירות יומית ובמייל. אפשר כמה התראות לחיפושים שונים.
2. **בג׳ימייל, יצירת פילטר:**
   - בשורת החיפוש כותבים `from:(jobalerts-noreply@linkedin.com)`, לוחצים על סמל ההגדרות שבתוך שורת החיפוש ואז "Create filter".
   - מסמנים "Apply the label", יוצרים תווית חדשה בשם `jobradar` ו‑"Create filter".
   - אם רוצים שההתראות לא יציפו את תיבת הדואר, מסמנים גם "Skip the Inbox".
3. **סיסמת אפליקציה (App Password):** נכנסים ל‑myaccount.google.com/apppasswords. זה דורש שאימות דו‑שלבי יהיה פעיל. יוצרים סיסמה בשם "JobRadar" ומדביקים ב‑`.env`:
   ```
   GMAIL_APP_PASSWORD=abcd efgh ijkl mnop
   ```
   הגישה היא לקריאה בלבד, ורק לתווית `jobradar`.
4. **ב‑`config/config.yaml`:**
   ```yaml
   gmail:
     enabled: true
     user: you@gmail.com       # הכתובת שלך
   ```
5. בודקים: `jobradar test-sources --only gmail`

**מה מקבלים מזה:** כותרת, חברה, מיקום וקישור, בלי תיאור משרה. לכן:
- אם אותה משרה קיימת גם באתר הקריירה של חברה ברשימה שלך, הכלי מזהה את הכפילות ומעריך את הגרסה המלאה.
- אחרת היא מגיעה כ"התאמה קלה" בפינג מרוכז. כדי לקבל הערכה מלאה, מעתיקים את תיאור המשרה מלינקדין ומריצים `jobradar paste <id>`.

את AllJobs, Drushim ואתרים דומים מוסיפים באותה דרך. יש דוגמה ב‑`config.example.yaml` תחת `email_sources`. את ה‑`link_pattern` כדאי לאמת מול מייל אמיתי, כי לא בדקתי את הפורמט שלהם.

## 9. הרצה ראשונה וכיול ⌨️ ✍️

```bash
jobradar fetch          # משיכה ומסננים, בלי מודל
jobradar filter-test    # לוודא שהמסננים לא פוסלים דברים שכן מעניינים
jobradar calibrate      # כ-25 משרות: g / o / b ומשפט "למה"
jobradar run            # הרצה מלאה
```

**הכיול הוא הדרך שלך ללמד את המודל בלי ז׳רגון.** מדרגים לפי תחושת בטן אמיתית, וכותבים משפט אחד למה. למשל:
- "טכנולוגיה מעולה אבל זה בעצם תפקיד תמיכה"
- "בדיוק מה שאני רוצה, למרות שהכותרת מוזרה"

ה"למה" הזה הופך לדוגמה שהמודל רואה בכל הערכה.

**בהרצה הראשונה** עלולות להיות מאות משרות פתוחות. המערכת מעבדת עד 200 בסינון המהיר ועד 12 בהערכה המעמיקה בכל הרצה, ומה שנשאר ממתין להרצה הבאה. אם רוצים לסיים מהר יותר, אפשר להריץ ידנית: `jobradar run --no-fetch --max-triage-calls 20 --max-deep 30`.

## 11. נטוורקינג 🧑 ⌨️ (מומלץ)

פירוט מלא: [NETWORKING.md](NETWORKING.md). בקצרה:
1. מורידים את רשימת הקשרים מלינקדין: **Settings & Privacy → Data privacy → Get a copy of your data → Connections**. הקובץ מגיע במייל.
2. מייבאים: `jobradar net import-linkedin Connections.csv`
3. מסמנים מי באמת מכיר אותך (הסוכן עובר על זה איתך): `jobradar net update "<שם>" --strength 3 --relationship friend`
4. מכאן והלאה רושמים שיחות במשפט רגיל לסוכן, או עם `/log`.

## מכסת השימוש של הפרו

- המערכת משתמשת **באותה מכסה כמו הצ׳אט שלך**. הרצה יומית רגילה היא בערך 2–8 קריאות Haiku ועד 12 קריאות Sonnet.
- אם המכסה נגמרת באמצע הרצה, המערכת עוצרת את שלבי המודל ושומרת את המשרות שלא טופלו להרצה הבאה. שום דבר לא הולך לאיבוד.
- אפשר להוריד את הצריכה עם `deep.max_per_run` ו‑`triage.max_calls_per_run` ב‑`config.yaml`, ועם מסנני כותרת הדוקים יותר.

## פתרון תקלות

| תסמין | פתרון |
|---|---|
| `Claude Code not found` | בטרמינל חדש מריצים `which claude` (ב‑Windows: `where claude`) ושמים את הנתיב המלא ב‑`llm.claude_bin`. |
| שגיאה על `--setting-sources` | מעדכנים את Claude Code (`claude update`). אם זה לא עוזר, ב‑`config.yaml` משנים ל‑`setting_sources: null` |
| שגיאה על `--tools` או `--strict-mcp-config` | מעדכנים את Claude Code (`claude update`). אם זה לא עוזר, מוחקים את הדגל מ‑`llm.isolation_args`. |
| `Not logged in` / `Login expired` בהרצה מתוזמנת | שלב 6: הטוקן ב‑`.env`. |
| מקור מסוים נכשל כל יום | `jobradar test-sources --only <name>`. ייתכן שהחברה עברה מערכת גיוס, ואז מריצים `detect` מחדש. |
| Gmail: `label not found` | שם התווית ב‑`config.yaml` צריך להיות זהה לשם בג׳ימייל. |
| Gmail: `Invalid credentials` | הסיסמה צריכה להיות App Password, לא הסיסמה הרגילה, ואימות דו‑שלבי צריך להיות פעיל. |
